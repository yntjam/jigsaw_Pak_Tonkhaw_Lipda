# 🧩 เกมต่อจิ๊กซอว์ – แข่งความเร็ว (Turso)

โปรแกรมตัวอย่างสำหรับฝึกเขียนเว็บแอปที่ต่อฐานข้อมูลบนคลาวด์ ทั้งหมดอยู่ในไฟล์ `index.html` ไฟล์เดียว (HTML + CSS + JavaScript) ไม่ต้องติดตั้งอะไรเพิ่ม

## ความสามารถ
- แนบรูปเองได้ (โปรแกรมครอปเป็นสี่เหลี่ยมจัตุรัสให้อัตโนมัติ) หรือใช้รูปตั้งต้น
- เลือกจำนวนชิ้นได้ 9 / 16 / 25 / 36 / 49 / 64 ชิ้น
- จับเวลาและนับจำนวนครั้งที่ย้ายชิ้น
- มี 3 โหมด
  1. **เล่นคนเดียว**
  2. **2 คน ผลัดกันเล่น** บนเครื่องเดียว โดยทั้งสองคนได้ชิ้นที่สลับไว้เหมือนกัน แล้วเทียบเวลากัน
  3. **2 คน แข่งพร้อมกัน** บน 2 เครื่อง คนหนึ่งสร้างห้องแล้วได้รหัส 4 หลัก อีกคนกรอกรหัสเข้าห้อง ระหว่างเล่นจะเห็นความคืบหน้าของคู่แข่งแบบสด
- บันทึกผลลง Turso และดูตารางคะแนนได้ (กรองตามจำนวนชิ้นได้)
- ถ้ายังไม่ได้ตั้งค่า Turso จะบันทึกผลไว้ในเบราว์เซอร์แทน ส่วนโหมด 2 เครื่องต้องใช้ Turso

## วิธีตั้งค่า Turso
1. สมัครที่ https://turso.tech แล้วสร้าง Database ใหม่
2. คัดลอก **Database URL** ที่ขึ้นต้นด้วย `libsql://...turso.io`
3. สร้าง **Token** จากหน้าเว็บ (ปุ่ม Create Token) หรือใช้คำสั่ง `turso db tokens create <ชื่อฐานข้อมูล>`
4. เปิด `index.html` กดปุ่ม **⚙️ ฐานข้อมูล** วาง URL และ Token แล้วกด **ทดสอบและบันทึก**
   โปรแกรมจะสร้างตาราง `results` และ `rooms` ให้เอง (ดูโครงสร้างได้ใน `schema.sql`)

> ⚠️ **เรื่องความปลอดภัย:** Token จะเก็บไว้ในเบราว์เซอร์ของเครื่องนั้น ใครที่เข้าถึงเครื่องหรือเปิด DevTools ได้ก็จะเห็น Token ด้วย จึงควรสร้างฐานข้อมูลแยกไว้ใช้ในห้องเรียนเท่านั้น ถ้าจะนำไปใช้งานจริง ควรมี Backend (เช่น Node.js) เป็นตัวกลางที่เก็บ Token ไว้ฝั่งเซิร์ฟเวอร์ ซึ่งเป็นหัวข้อที่ดีสำหรับให้นักเรียนอภิปรายต่อ

## เปิดใช้งานด้วย GitHub (ไม่ต้องติดตั้งโปรแกรม)
ทุกขั้นทำผ่านเบราว์เซอร์ จึงใช้ได้กับคอมของโรงเรียนที่ติดตั้งโปรแกรมไม่ได้
1. สมัคร **github.com** แล้วสร้าง repository ชื่อ `jigsaw` แบบ **Public** และติ๊ก Add a README file
2. ในหน้า repository กดปุ่ม **.** (จุด) เพื่อเปิด **github.dev** แล้วสร้างไฟล์ `index.html`
3. เขียนโค้ดเสร็จ ไปที่ไอคอน Source Control พิมพ์ข้อความสั้น ๆ แล้วกด **Commit & Push**
4. ที่ github.com เข้า **Settings › Pages** เลือก Deploy from a branch, branch **main**, โฟลเดอร์ **/ (root)** แล้วกด Save
5. รอ 1–2 นาที จะได้ลิงก์เกม เช่น `https://ชื่อผู้ใช้.github.io/jigsaw/`

ทุกครั้งที่แก้โค้ด ให้ทำตามวงจร **แก้ → Commit → รอ 1 นาที → Ctrl+F5 ที่หน้าเกม**

> ⚠️ repository แบบ Public ใครก็เปิดดูโค้ดได้ **ห้ามวาง Token ลงในโค้ด** ให้กรอกผ่านปุ่ม ⚙️ ในเกมเท่านั้น

**ทางสำรอง (เข้า GitHub ไม่ได้):** เขียนด้วย Notepad บันทึกเป็น `index.html` (Save as type: All files, Encoding: UTF-8) แล้วดับเบิลคลิกไฟล์เพื่อเปิดเกม

**โหมด 2 เครื่อง:** ทั้งสองเครื่องต้องตั้งค่า Turso ด้วย URL และ Token ชุดเดียวกัน

## โครงสร้างโค้ด (ใน `<script>`)
| ส่วน | หน้าที่ |
|---|---|
| 1 ตัวช่วยทั่วไป | `fmt()` แปลงเวลา, `shuffle()` สุ่มลำดับชิ้น, `show()` สลับหน้าจอ |
| 2 เชื่อมต่อ Turso | `sql(query, params)` ส่งคำสั่ง SQL ไปที่ `/v2/pipeline` และ `initTables()` |
| 3 บันทึก/อ่านคะแนน | `saveResult()`, `loadBoard()` |
| 4 รูปภาพ | `loadImageFile()` อ่านไฟล์ → `cropToSquare()` ย่อเหลือ 500×500 |
| 5 ตัวเกม | `class Puzzle` เก็บ `order[ตำแหน่ง] = หมายเลขชิ้น` ต่อเสร็จเมื่อ `order[i] === i` |
| 6 เวลา | `timer`, `countdown()`, `poll()` |
| 7 โหมดการเล่น | `startSolo()`, `startTurn()`, `hostRoom()` / `joinRoom()` / `beginOnline()` |
| 8 ปุ่มต่าง ๆ | เชื่อมปุ่มบนหน้าจอเข้ากับฟังก์ชัน |

**หลักการของโหมด 2 เครื่อง:** ทั้งสองเครื่องไม่ได้คุยกันโดยตรง แต่ใช้ตาราง `rooms` เป็นตัวกลาง เครื่องแต่ละเครื่องเขียนความคืบหน้าของตัวเองลงไป แล้ว **poll** (อ่านซ้ำทุก 1.5 วินาที) เพื่อดูข้อมูลของอีกฝั่ง เวลาเริ่มเกมกำหนดด้วย `started_at` เพื่อให้นับถอยหลังพร้อมกัน

## ตัวอย่างงานให้นักเรียนพัฒนาต่อ
1. **พื้นฐาน:** เปลี่ยนสีธีม เพิ่มตัวเลือก 100 ชิ้น (10×10) หรือเพิ่มเสียงตอนต่อเสร็จ
2. **SQL:** ทำหน้า "สถิติของฉัน" แสดงจำนวนครั้งที่เล่น เวลาเฉลี่ย และสถิติดีที่สุด (มีตัวอย่างใน `schema.sql`)
3. **ตรรกะเกม:** เปลี่ยนจากคลิกสลับเป็นการลากวาง (Drag & Drop) หรือให้ชิ้นที่ถูกที่แล้วล็อกไว้
4. **ฐานข้อมูล:** เพิ่มตาราง `players` แล้วเชื่อมกับ `results` ด้วย `player_id` (Foreign Key)
5. **ความยุติธรรม:** ทำโหมดที่ให้ทุกคนในห้องใช้รูปและชุดสลับเดียวกัน (Daily Challenge)
6. **ท้าทาย:** ขยายห้องแข่งให้รองรับมากกว่า 2 คน
